## 规则 D1：数据结构课必须有「为什么用这个」

**来源**：学数据结构最容易变成「背复杂度」。

**要求**：每介绍一个结构，必须回答三个问题：

1. **它解决什么问题？**（不是「它是什么」）
2. **不用它会怎样？**（给出量化后果）
3. **什么时候不该用它？**

**示例**：

> ❌ 差：“哈希表是 O(1) 查找的数据结构。”
> ✅ 好：“如果你要每帧查询 1 万个敌人的属性，线性查找每帧 1 万次；哈希表只需 1 万次 O(1) 查询。但如果你只查 3 个敌人，哈希表的建表开销比线性查找更大。”

## 规则 D2：必须手写，且必须自己测试

**来源**：只看不写等于没学。

**要求**：

- **手写实现**（不调用标准库）
- **自己写测试**：正常情况 + 边界情况（空、满、单个元素）+ 异常情况
- **分析复杂度**：时间 + 空间，写在注释里

**测试模板：**

```cpp
void test_xxx()
{
    // 1. 空容器
    // 2. 单个元素
    // 3. 多个元素
    // 4. 边界（越界、满、空）
    // 5. 大量元素（性能）
}
```

## 规则 D3：复杂度要说「怎么算出来的」

**来源**：背 O(n) 没用，要能现场推。

**要求**：解释复杂度时，**必须说清算了几次操作**。

**示例**：

> “`push_back` 是均摊 O(1)——因为扩容时复制（每次 O(n)）但只在容量翻倍时发生，摊到每次插入上就是 O(1)。”

## 规则 D4：性能对比必须有实测数字

**来源**：主课表 `vector` vs `list` 实测差 70 倍，数字比理论更有说服力。

**要求**：涉及性能断言时，**用 `std::chrono` 实测**，贴真实结果。

## 规则 D5：区分「面试要手写」和「工作用标准库」

**来源**：学生可能困惑「既然有 `std::stack`，为什么还要自己写」。

**要求**：每课开头明确该结构属于哪一类：

| 类别 | 要求 |
|---|---|
| **面试必写** | 链表、二叉树、BST、堆、哈希表、图、并查集 |
| **工作直接用** | `stack`/`queue`/`priority_queue`/`unordered_map` |
| **知道即可** | 红黑树、四叉树、B 树 |

# 一之二、数据结构课的授课方式（与 C++ 基础课不同）

> **来源**：D2 时我一次讲了 13 个函数 + 200 行代码，学生反馈「完全跟不上」。
> 改成**分步骤实现**后，学生每一步都能编译跑通，跟得上了。
> D1 时改成**出题代替写代码**，学生也接受。
>
> **结论：C++ 基础课和数据结构课的教学方式必须不同。**

## 为什么不同

| | C++ 基础课（cpp-learning） | 数据结构课（本课） |
|---|---|---|
| **学什么** | 语法、用法 | 原理 + 实现 |
| **学生要做的** | **照着示例写一遍** | **从零想出来** |
| **示例的作用** | 给结构参考 | **给答案 = 剥夺练习** |
| **一节课的量** | 3–5 个新概念 | **1 个结构 + 它的所有函数** |
| **代码量** | 20–50 行 | **100–200 行** |

**核心差别：**

> **基础课是「示范 → 模仿」，数据结构课是「讲解 → 自己实现」。**
> **所以基础课可以先给完整 `lessonNN.cpp`，数据结构课不能。**

## 规则 D6：不给完整实现，只给分步骤骨架

**来源**：D2 一次给 13 个函数，学生跟不上。

**做法**：

**把一个结构的实现拆成 3–4 个步骤，每步只加 2–5 个函数，每步都能编译运行。**

**示例（D2 的拆法）：**

| 步骤 | 加什么 | 能验证什么 |
|---|---|---|
| 1 | 构造、析构、`push_back`、`size`、`capacity`、`grow` | 能装东西、容量按倍增长 |
| 2 | 两个 `operator[]` | 能读能写 |
| 3 | 拷贝构造、拷贝赋值 | 深拷贝正确 |
| 4 | `pop_back`、`clear`、`empty`、`reserve` | 边界都安全 |

**每步结束都有「预期输出」，学生对照即可自检。**

**禁止**：一次给完整实现让学生照抄。

## 规则 D7：只给「难的片段」，不给能照抄的整体

**来源**：D2 步骤 1 如果我把整个 `MyVector` 写出来，学生没有思考空间。

**做法**：

| 函数类型 | 给不给参考 |
|---|---|
| **构造/析构/一行 getter** | ❌ 不给，学生写 |
| **核心算法**（`grow`、深拷贝） | ✅ **给骨架，并逐行讲解** |
| **边界处理**（`pop_back` 的空检查） | ⚠️ 只给「要注意什么」，不给代码 |

**理由**：难点给参考才不会卡死，简单的自己写才有练习量。

## 规则 D8：讲解必须覆盖「你可能没见过的写法」

**来源**：D2 的 `#pragma once`、`template <typename T>`、`T *data_ = nullptr`、`data_` 尾部下划线，学生有些没见过。

**做法**：每给一段代码，**逐行说明**：

1. 这一行做什么
2. 为什么这么写
3. 不这么写会怎样
4. 有没有你没见过的语法（标注出来）

**具体到本项目，必须解释的「新写法」清单：**

| 写法 | 出现在 | 说明要点 |
|---|---|---|
| `#pragma once` | 所有 `.h` | 防重复包含 |
| `T *data_ = nullptr` | 类成员 | **成员声明处默认值**（新写法） |
| **成员名末尾 `_`** | `data_` / `size_` | 避免和函数名 `size()` 冲突 |
| `= default` | 默认构造 | 让编译器生成 |
| `new T[n]` / `delete[]` | `grow` | **必须配对** |
| `? :` 三元 | `grow` | 首次扩容特判 |
| `std::size_t` | 所有下标 | 无符号大小类型 |
| **类模板** | `template<typename T> class` | 和函数模板的区别：**必须显式写类型** |

## 规则 D9：学生提问时，先纠正「措辞」再回答内容

**来源**：D2 学生问「`&other = a` 是不是地址一样」，把「取值」和「取地址」混了。

**做法**：

**学生用错了术语时，先纠正措辞，再回答实质问题。**

**示例**：

> 学生：「`&other = a`，那么变量 other 的地址和 a 一样吗？」
>
> 老师：「先纠正：`&other` 是地址，它等于 `&a`，不是等于 `a`（那是值）。回答：一样，因为引用没有独立地址。」

**理由**：术语错了，理解一定偏。**纠正措辞比纠正结论更根本。**

## 规则 D10：用「一句话总结」收尾每个知识点

**来源**：学生多次问「所以是不是……」，说明需要一句话压缩版。

**做法**：每讲完一个概念，给一句**能背下来**的总结：

**示例**：

> - 「`&` 在声明里是引用，在表达式里是取地址。」
> - 「引用是别名，不是变量。」
> - 「问题不是指针有没有析构函数，而是有几个对象负责释放。」

**这些句子要在后续课程中反复引用。**

## 两种课型怎么选

| 课的内容 | 用什么方式 |
|---|---|
| **纯概念**（如 D1 复杂度） | **出题 + 给答案对照**（学生做，批改） |
| **写实现**（如 D2 动态数组） | **分步骤 + 只给难片段** |
| **算法题**（A 阶段） | **出题 + 提示 + 批改** |

**判断标准**：

> **学生需要「动手想」还是「动手抄」？**
> **需要想 → 给题目/分步骤；需要抄 → 才给完整示例。**

# 二、环境备忘

## 编译命令

```
g++ -std=c++17 -Wall -Wextra -o app.exe 源文件.cpp
```

**多文件：**

```
g++ -std=c++17 -Wall -Wextra -o app.exe main.cpp xxx.cpp
```

**性能测试建议加 `-O2`：**

```
g++ -std=c++17 -O2 -Wall -Wextra -o bench.exe bench.cpp
```

> ⚠️ **`-O2` 会优化掉“没用到的计算”**——测性能时要把结果打印出来或用 `volatile`，否则测的是 0 秒。

## 测试输入

**与主课表相同：**

```
cmd /c "prog.exe < input.txt"
```

**`input.txt` 用 ASCII 编码，行尾 `\r\n`。**

## 计时模板

```cpp
#include <chrono>

auto t0 = std::chrono::steady_clock::now();
// ... 被测代码 ...
auto t1 = std::chrono::steady_clock::now();
auto us = std::chrono::duration_cast<std::chrono::microseconds>(t1 - t0).count();
std::cout << us << " 微秒\n";
```
